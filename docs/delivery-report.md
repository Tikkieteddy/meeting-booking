## 3. ฟีเจอร์ที่ทำเสร็จ

### ปฏิทินและการจอง
- ปฏิทินเต็มพื้นที่ สลับ วัน/สัปดาห์/เดือน ทีละมุมมอง โดยห้อง วันที่ และตัวกรองคงค่าเดิม (เก็บใน URL จึงแชร์ลิงก์และกดย้อนกลับได้)
- Day View: เส้นเวลาปัจจุบันสีแดงพร้อมป้ายเวลา, เลื่อนไปใกล้เวลาจริงอัตโนมัติ, กดช่องว่างเพื่อจอง, เลือก "ทุกห้อง" แล้วแสดงคอลัมน์รายห้อง
- Week View: หัววันคงที่, เลื่อนแนวนอนได้บนแท็บเล็ต, รายการที่ทับกันแบ่งคอลัมน์ไม่ซ่อนข้อมูล
- Month View: จุดสี 4 ระดับพร้อมข้อความและสัญลักษณ์กำกับ, กดวันแล้วเปิด Day View, วันหยุดมีสัญลักษณ์และ tooltip
- ฟอร์มจองเป็น Drawer ไม่พาออกจากปฏิทิน พร้อม idempotency key กันกดซ้ำ
- กันจองซ้อนด้วย exclusion constraint ที่ฐานข้อมูล รวมเวลา buffer หน้า/หลัง
- จองซ้ำรายวัน/สัปดาห์/เดือน ครั้งที่ชนเวลาถูกข้ามและรายงานกลับ
- แก้ไขด้วย optimistic concurrency (`version`) กันสองคนแก้ทับกัน
- ยกเลิกทีละรายการหรือทั้งชุด พร้อมยืนยันและระบุเหตุผล
- ดาวน์โหลดไฟล์ปฏิทิน `.ics`

### ค้นหา
- ช่องเดียวรองรับสามกรณี: ห้อง / ชื่อผู้จอง / ช่วงเวลาว่าง
- ตีความคำค้นภาษาไทยแบบผสม เช่น "พรุ่งนี้ 13:00 ถึง 15:00 12 คน ทีวี"
- ตัวกรองเพิ่มเติม, filter chip ลบทีละเงื่อนไข, ล้างทั้งหมด, จำคำค้นล่าสุดในเครื่อง
- debounce 300 มิลลิวินาที และยกเลิก request เก่าอัตโนมัติ

### ยืนยันตัวตนและสิทธิ์
- สมัคร/เชิญผู้ใช้, ยืนยันอีเมล, ลืมรหัสผ่าน, เปลี่ยนรหัสผ่าน, ออกจากระบบทุกอุปกรณ์
- จำกัดอัตราการล็อกอิน สมัคร ค้นหา และการจอง
- RBAC 5 role พร้อมขอบเขต องค์กร/อาคาร/ห้อง/แผนก
- ตรวจสิทธิ์สามชั้น: UI → API → RLS ที่ฐานข้อมูล (เปิด `FORCE ROW LEVEL SECURITY`)
- ปิดบังข้อมูลการประชุมส่วนตัวที่ชั้นฐานข้อมูลด้วย view

### อนุมัติ เช็กอิน คิวรอ
- คิวรออนุมัติ พร้อมอนุมัติ/ปฏิเสธ (บังคับระบุเหตุผล)/ขอข้อมูลเพิ่ม
- เช็กอินตามช่วงเวลา และ cron ปล่อยห้องคืนเมื่อไม่มีการเช็กอิน
- คิวรอห้องว่าง เสนอสิทธิ์ตามลำดับพร้อมเวลาหมดอายุ

### การแจ้งเตือน
- อีเมล (Resend) และ LINE Messaging API พร้อมโหมด `log` สำหรับทดสอบโดยไม่ต้องมีคีย์
- Template อีเมลไทยแบบ responsive + แนบไฟล์ `.ics`
- คิวงานพร้อม idempotency key, retry แบบ exponential backoff, dead letter, บันทึกผลทุกครั้ง
- Webhook LINE และอีเมล ตรวจลายเซ็นทุก request
- เชื่อมบัญชี LINE ด้วยรหัสใช้ครั้งเดียวอายุ 15 นาที รองรับ unlink และ block
- ศูนย์การแจ้งเตือนในระบบ และตั้งค่าช่องทาง/เวลาเตือนรายบุคคล

### หลังบ้าน
- Dashboard: จำนวนการจอง, อัตราใช้ห้อง, ชั่วโมงใช้งาน, peak time, ยกเลิก, ไม่มาใช้ห้อง, ห้องยอดนิยม
- รายงานพร้อมตัวกรองและ Export CSV (มี BOM ให้ Excel อ่านไทยได้)
- จัดการห้องครบนโยบายรายห้อง, เก็บเข้าคลังแทนการลบ, ปิดห้องกะทันหันพร้อมแจ้งผู้ได้รับผลกระทบ
- จัดการผู้ใช้ เชิญผู้ใช้ กำหนด Role และกันไม่ให้เหลือ super admin เป็นศูนย์
- Audit log ค้นหาได้ อ่านได้เท่านั้น แก้ไขย้อนหลังไม่ได้
- หน้าสถานะระบบ: คิวงาน ความผิดพลาดล่าสุด สั่งส่งใหม่ โดยไม่เปิดเผย secret

### ประสบการณ์ใช้งาน
- ภาษาไทยทั้งระบบผ่านโครงสร้าง i18n (เตรียมภาษาอังกฤษไว้แล้ว)
- Guided tour 5 ขั้น ข้ามได้ เปิดดูใหม่ได้ + หน้าช่วยเหลือ FAQ
- Skeleton, Empty, Error, **Offline** และ Retry state
- Keyboard navigation, focus trap, คืน focus, ปิดด้วย Esc, เป้าแตะ 44px, เคารพ `prefers-reduced-motion`
- สถานะไม่สื่อด้วยสีอย่างเดียว — มีข้อความและสัญลักษณ์กำกับทุกที่

### สิ่งที่เทสต์ครอบคลุมเป็นพิเศษ

- **Race condition:** ยิง 10 คำขอจองห้องเดียวกันช่วงเดียวกันพร้อมกัน → สำเร็จ 1 รายการเสมอ
- **Authorization matrix:** ทดสอบทั้ง 5 role ทั้งที่ชั้น UI, API และ RLS
- **ความเป็นส่วนตัว:** การประชุม `private` ของผู้อื่นไม่ปรากฏในผลลัพธ์เลย, `busy_only` ถูกปิดบังหัวข้อและชื่อผู้จอง
- **Audit log ไม่สามารถแก้ไข:** ทดสอบว่า UPDATE/DELETE ไม่มีผลแม้เป็น super admin
- **Timezone:** ข้ามวัน ข้ามเดือน ข้ามปี และปีอธิกสุรทิน
- **Buffer:** ช่วงที่ดูเหมือนว่างแต่ชนเพราะ buffer ถูกปฏิเสธถูกต้อง
- **Responsive:** 360 / 768 / 1024 / 1440 px ไม่มีการเลื่อนแนวนอน
- **Accessibility:** skip link, focus trap, คืน focus, aria-selected, label ครบทุกฟิลด์, ซูม 200%

## 5. วิธีรันและตรวจสอบด้วยตนเอง

### รันบนเครื่องตัวเอง

```bash
npm install
cp .env.example .env.local     # เติม DATABASE_URL และ AUTH_SECRET
createdb tnn_meeting && createdb tnn_meeting_test
npm run db:migrate && npm run db:seed
npm run dev                    # http://localhost:3000
```

บัญชีตัวอย่าง (รหัสผ่าน `TnnDemo2569!`) — ดูตารางใน [../README.md](../README.md)

### ตรวจฟีเจอร์หลักด้วยตนเอง (ใช้เวลาประมาณ 10 นาที)

1. ล็อกอินด้วย `user1@example.com` → เห็น guided tour → กดข้าม
2. สลับ วัน / สัปดาห์ / เดือน → สังเกตว่าเปลี่ยนทีละมุมมอง และห้อง/วันที่คงเดิม
3. มุมมองเดือน → กดวันใดวันหนึ่ง → เปิด Day View ของวันนั้น
4. กดช่องเวลาว่างในมุมมองวัน → ฟอร์มเปิดพร้อมใส่ห้อง/วัน/เวลาให้แล้ว → จอง
5. จองซ้ำช่วงเวลาเดิม → ต้องได้ข้อความบอกว่าชนกับรายการใด
6. ใส่จำนวนคนเกินความจุ → ต้องได้ error ติดฟิลด์
7. ค้นหา `พรุ่งนี้ 13:00 ถึง 15:00 6 คน` → ต้องได้ห้องว่างพร้อมปุ่มจองเลย
8. จองห้อง `ห้องประชุมใหญ่ ชั้น 3` (ต้องอนุมัติ) → สถานะ "รออนุมัติ"
9. ล็อกอินเป็น `approver@example.com` → หน้า "รออนุมัติ" → กดปฏิเสธโดยไม่ใส่เหตุผล (ต้องเตือน) แล้วอนุมัติ
10. ล็อกอินเป็น `admin@example.com` → เพิ่มห้องใหม่ → กลับไปหน้าปฏิทิน ห้องต้องโผล่ในตัวเลือกทันที
11. หน้า **สถานะระบบ** → เรียก cron ด้วยมือแล้วดูว่างานถูกส่ง

```bash
curl -H "authorization: Bearer dev-cron-secret" http://localhost:3000/api/cron/dispatch
```

12. กลับเป็น `user1@example.com` → พิมพ์ `/admin` ใน URL → ต้องถูกพากลับหน้าปฏิทิน
13. ย่อหน้าต่างเป็นความกว้างมือถือ → ต้องใช้งานได้และไม่มีแถบเลื่อนแนวนอน

### รันเทสต์

```bash
npm run verify            # typecheck + lint + unit
npm run test:integration  # ต้องมี TEST_DATABASE_URL
npm run test:e2e          # ล้างและ seed ฐานข้อมูลให้ก่อนอัตโนมัติ
```

## 6. ข้อจำกัดที่ทราบ (Known Limitations)

| เรื่อง | รายละเอียด | ผลกระทบ | สิ่งที่ต้องทำถ้าต้องการ |
|---|---|---|---|
| ยังไม่มี SSO | บรีฟข้อ 7.1 ระบุว่า "เตรียมจุดเชื่อมไว้ภายหลัง" | ผู้ใช้ต้องจำรหัสผ่านของระบบนี้ | ต่อ Google Workspace / Entra ID ที่ `src/lib/auth/` |
| ยังไม่มีอัปโหลดไฟล์แนบและรูปห้อง | โครงสร้างรองรับ URL รูปแล้ว แต่ยังไม่มีหน้าอัปโหลด | ใส่ URL รูปที่โฮสต์ไว้แล้วได้ทันที | ตั้ง Supabase Storage bucket + RLS policy |
| เช็กอินยังไม่มี QR code | บรีฟระบุ "ด้วยปุ่มหรือ QR Code" — ทำปุ่มไว้ และเก็บ `check_in_token` พร้อมแล้ว | เช็กอินผ่านหน้าเว็บได้ปกติ | สร้างหน้า `/check-in/[token]` และ QR ติดหน้าห้อง |
| ปฏิทินไม่ใช่ realtime | โหลดใหม่เมื่อเปลี่ยนมุมมอง/วัน/ห้อง และหลังทำรายการ | อาจเห็นข้อมูลช้ากว่าจริงไม่กี่วินาที | เปิด Supabase Realtime บนตาราง `bookings` |
| การแจ้งเตือนหน่วงตามรอบ Cron | สูงสุด 5 นาที | อีเมลยืนยันมาช้ากว่ากดจองเล็กน้อย | เรียก worker ตรงหลังบันทึกสำเร็จ (ไม่ต้องแก้โครงสร้าง) |
| ภาษาอังกฤษแปลบางส่วน | โครงสร้าง i18n ครบ ไทยครบ อังกฤษแปลคำที่ใช้บ่อย | คีย์ที่ยังไม่แปลจะ fallback เป็นไทย | เติมคีย์ใน `src/lib/i18n/en.ts` |
| ยังไม่มีหน้าสร้าง custom role | ตาราง `roles`/`role_permissions` รองรับแล้ว | เพิ่ม role ใหม่ต้องทำผ่าน SQL | ทำหน้า UI จัดการ role |
| ยังไม่ได้ทดสอบกับ Supabase/Vercel จริง | เซสชันนี้ไม่มีคีฟของบัญชีผู้ใช้ (และไม่ควรมี) | ทดสอบครบบน PostgreSQL 16 จริงในเครื่องแล้ว | ทำตาม [infrastructure-setup.md](infrastructure-setup.md) แล้วเดิน [production-readiness.md](production-readiness.md) |
| `vitest` 2.1.9 มีช่องโหว่ที่ยังไม่มีเวอร์ชันแก้ในสาย 2.x | 1 critical + 3 ระดับรองในเครื่องมือทดสอบ — สายที่แก้แล้วคือ 5.x ซึ่งข้าม 3 major version | **เป็น dependency ของนักพัฒนาเท่านั้น ไม่ได้ขึ้น production** · ช่องโหว่ระดับ critical เกิดเฉพาะเมื่อรัน `vitest --ui` ซึ่งโปรเจกต์นี้ไม่ใช้ | อัปเกรด `vitest` เป็น 5.x แล้วรัน `npm run test:unit` กับ `npm run test:integration` ให้ผ่าน — config ใช้ option พื้นฐานทั้งหมด คาดว่าแก้ไม่มาก |
| สีส้มแบรนด์กับตัวอักษรขาวยังไม่ผ่านเกณฑ์ contrast | `#EC5F27` กับตัวอักษรขาวได้ 3.36:1 ต้องได้ 4.5:1 — พบที่ปุ่มหลักและป้ายต่าง ๆ | คนสายตาเลือนอ่านตัวหนังสือบนปุ่มได้ยากกว่าที่ควร · คะแนน Accessibility ค้างที่ 96 | เป็นการตัดสินใจเรื่องสีแบรนด์ ไม่ใช่เรื่องเทคนิค — เลือกเฉดจากตารางใน [performance.md](performance.md) ข้อ 7 แล้วแก้ token จุดเดียว |
| ยังไม่ได้ทดสอบ PWA บนมือถือเครื่องจริง | ทดสอบครบใน Chromium (แคช หน้าออฟไลน์ manifest ไอคอน) แต่ยังไม่เคยกด "เพิ่มลงหน้าจอหลัก" บน iPhone/Android จริง | อาจมีรายละเอียดการแสดงผลต่างจากที่คาด | ติดตั้งจริงหลังขึ้น production แล้วดูตามหัวข้อวิธีติดตั้งในหน้าช่วยเหลือ |
| ยังไม่ได้ทดสอบส่งอีเมล/LINE จริง | ใช้โหมด `log` ซึ่งบันทึกลง log และฐานข้อมูลจริง | flow ทั้งหมดทดสอบได้ แต่ยังไม่เคยส่งออกภายนอก | ใส่คีย์ Resend และ LINE แล้วทดสอบตามข้อ 4.6 และ 5.4 ของคู่มือ Infrastructure |

## 7. งานต่อเนื่องที่แนะนำ (เรียงตามความสำคัญ)

1. **ตั้งค่า Supabase + Vercel + DNS จริง** ตาม [infrastructure-setup.md](infrastructure-setup.md)
   แล้วเดิน [production-readiness.md](production-readiness.md) ให้ครบ
2. **ใส่คีย์ Resend และ LINE** แล้วทดสอบส่งไป Gmail / Outlook / อีเมลองค์กร
3. **ใส่ข้อมูลห้องประชุมจริง** ความจุ อุปกรณ์ เวลาทำการ และนโยบายรายห้อง
4. **สร้างบัญชีผู้ดูแลระบบสูงสุด 2 คน** แล้วเชิญผู้ใช้เข้าระบบ
5. **ทดสอบกู้คืนฐานข้อมูลจาก backup จริง** และบันทึกผล
6. เปิด branch protection ให้ต้องผ่าน CI (`.github/workflows/ci.yml`) ก่อน merge
7. ตั้ง uptime monitor และ alert ตามข้อ 9 ของคู่มือ Infrastructure
8. หลังใช้งาน 1 เดือน ดูรายงาน "ไม่มาใช้ห้อง" แล้วพิจารณาเปิด "ต้องเช็กอิน" ในห้องที่เป็นปัญหา
