# คู่มือผู้ดูแลระบบ — ระบบจองห้องประชุม TNN

สำหรับผู้มีสิทธิ์ **ผู้ดูแลระบบสูงสุด** หรือ **ผู้ดูแลห้อง**

---

## 1. สิทธิ์ในระบบมีอะไรบ้าง

| Role | ทำอะไรได้ | เหมาะกับใคร |
|---|---|---|
| **ผู้ดูแลระบบสูงสุด** | ทุกอย่าง รวมกำหนดสิทธิ์ ตั้งค่าระบบ ดู audit log และสถานะระบบ | ฝ่าย IT 1–2 คน |
| **ผู้ดูแลห้อง** | เพิ่ม/แก้/ปิดห้องตามขอบเขต ดูและแก้การจองในความรับผิดชอบ อนุมัติ ดูรายงาน | ฝ่ายบริหารอาคาร |
| **ผู้อนุมัติ** | อนุมัติ/ปฏิเสธคำขอ ดูรายละเอียดการจอง | หัวหน้าฝ่ายที่ดูแลห้องสำคัญ |
| **พนักงาน** | จอง แก้ไข ยกเลิกของตัวเอง | พนักงานทั่วไป |
| **ผู้ชม / ประชาสัมพันธ์** | ดูตารางและสถานะว่าไม่ว่าง **จองไม่ได้** | เคาน์เตอร์ประชาสัมพันธ์ จอแสดงผลหน้าห้อง |

**หลักการให้สิทธิ์:** ให้น้อยที่สุดเท่าที่ทำงานได้ (least privilege)
และต้องมีผู้ดูแลระบบสูงสุดอย่างน้อย 2 คน เผื่อคนหนึ่งลาหรือลาออก

> ระบบกันไม่ให้ถอนสิทธิ์ผู้ดูแลระบบสูงสุดคนสุดท้าย — จะขึ้นข้อความ
> "ต้องมีผู้ดูแลระบบสูงสุดอย่างน้อยหนึ่งคน"

---

## 2. เช็กลิสต์เริ่มต้นใช้งาน

หน้า **ผู้ดูแลระบบ → ภาพรวมระบบ** มีเช็กลิสต์นี้แสดงสถานะให้เห็น

1. เพิ่มห้องประชุมจริงทั้งหมด พร้อมความจุและอุปกรณ์
2. ตั้งเวลาทำการและวันทำการของแต่ละห้อง
3. กำหนดว่าห้องไหนต้องขออนุมัติ และใครเป็นผู้อนุมัติ
4. เพิ่มวันหยุดขององค์กร
5. เชิญผู้ใช้เข้าระบบและกำหนด Role
6. ทดสอบจองหนึ่งรายการ แล้วตรวจว่าอีเมลและ LINE ออกจริง
7. ตรวจหน้า **สถานะระบบ** ว่าไม่มีงานค้าง

## 3. จัดการห้องประชุม

**เมนู:** ผู้ดูแลระบบ → จัดการห้อง

### เพิ่มห้องใหม่

กด **＋ เพิ่มห้องใหม่** แล้วกรอกข้อมูล

| กลุ่ม | ช่อง | คำแนะนำ |
|---|---|---|
| ข้อมูลพื้นฐาน | รหัสห้อง, ชื่อห้อง, อาคาร, ชั้น, ความจุ, ประเภทห้อง | รหัสห้องใช้ A-Z 0-9 . _ - เช่น `TNN-A-301` ตั้งให้สื่อถึงอาคารและชั้น |
| อุปกรณ์ | ทีวี โปรเจกเตอร์ ประชุมทางไกล ไวท์บอร์ด ไมโครโฟน ฯลฯ | ใส่ให้ครบ เพราะผู้ใช้ค้นหาห้องจากอุปกรณ์ |
| เวลาทำการ | เปิด, ปิด, วันทำการ | เช่น 08:00–20:00 จันทร์–ศุกร์ |
| กฎเวลา | ช่วงเวลาเป็นขั้น, จองขั้นต่ำ/สูงสุด, จองล่วงหน้าได้กี่วัน | ห้องเล็กใช้ขั้นละ 30 นาที ห้องใหญ่อาจใช้ 60 นาที |
| เวลาเตรียมห้อง | เวลาก่อน/หลังประชุม (buffer) | ห้องที่ต้องจัดโต๊ะหรือเก็บอุปกรณ์ควรตั้ง 15–30 นาที |
| นโยบาย | ต้องขออนุมัติ, ต้องเช็กอิน, เปิดใช้คิวรอ, ยกเลิกล่วงหน้าอย่างน้อย | ดูคำอธิบายด้านล่าง |

**ห้องใหม่จะปรากฏในตัวเลือก ค้นหา และปฏิทินทันที ไม่ต้องแก้โค้ดหรือ deploy ใหม่**

### นโยบายรายห้าง — เลือกให้เหมาะกับการใช้งานจริง

| นโยบาย | เปิดเมื่อไร | ผลที่เกิด |
|---|---|---|
| **ต้องขออนุมัติ** | ห้องใหญ่ ห้องผู้บริหาร ห้องที่มีค่าใช้จ่าย | การจองขึ้น "รออนุมัติ" และแจ้งผู้อนุมัติทันที |
| **ต้องเช็กอิน** | ห้องยอดนิยมที่มักถูกจองแล้วไม่มาใช้ | ถ้าไม่เช็กอินภายในเวลาผ่อนผัน ระบบปล่อยห้องคืนอัตโนมัติ |
| **เปิดใช้คิวรอ** | ห้องที่เต็มบ่อย | เมื่อมีคนยกเลิก ระบบแจ้งผู้รอคิวลำดับถัดไป |
| **ยกเลิกล่วงหน้าอย่างน้อย N นาที** | ห้องที่ต้องเตรียมคนหรืออุปกรณ์ | ผู้ใช้ยกเลิกเองไม่ได้เมื่อใกล้เวลา (ผู้ดูแลยังยกเลิกได้) |
| **เวลาเตรียมห้อง (buffer)** | ห้องที่ต้องจัดโต๊ะ/เก็บของ | ช่วง buffer ถูกกันไม่ให้ใครจองต่อทันที |

> ⚠️ **ถ้าตั้งว่า "ต้องขออนุมัติ" ต้องกำหนดผู้อนุมัติด้วย**
> ไม่อย่างนั้นคำขอจะค้างไม่มีใครอนุมัติได้ (ระบบจะบันทึกคำเตือนไว้ใน log)

### แก้ไขและเก็บห้องเข้าคลัง

- **แก้ไข** — เปลี่ยนนโยบายได้ตลอด การจองเดิมยังใช้ค่า buffer เดิมที่บันทึกไว้ตอนจอง
  จึงไม่กระทบรายการที่จองไปแล้ว
- **เก็บเข้าคลัง** — ใช้แทนการลบ ห้องจะหายจากตัวเลือกแต่ประวัติการจองและรายงานยังอยู่ครบ
- **นำกลับมาใช้** — กดได้ตลอด

> **ระบบไม่มีปุ่มลบห้อง** โดยเจตนา เพราะห้องที่มีประวัติการจองต้องคงไว้
> เพื่อรักษารายงานและบันทึกการใช้งาน

### ปิดห้องกะทันหัน (ช่วงปิดปรับปรุง)

เมื่อแอร์เสียหรือมีงานซ่อม ให้เพิ่ม **ช่วงปิดปรับปรุง** ระบุเวลาเริ่ม-สิ้นสุดและเหตุผล

ระบบจะ

1. กันไม่ให้จองใหม่ในช่วงนั้น
2. **แจ้งทุกคนที่มีการจองค้างอยู่ในช่วงนั้นทันที** พร้อมคำแนะนำให้เลือกห้องใหม่
3. แสดงแถบลายทแยงในปฏิทินให้เห็นชัด

> การจองเดิมจะ **ไม่ถูกยกเลิกอัตโนมัติ** เพื่อไม่ให้ข้อมูลหายโดยไม่มีใครรู้
> ผู้จองหรือผู้ดูแลต้องยกเลิกหรือย้ายห้องเอง

## 4. จัดการผู้ใช้และสิทธิ์

**เมนู:** ผู้ดูแลระบบ → ผู้ใช้และสิทธิ์

### เชิญผู้ใช้

กด **เชิญผู้ใช้** กรอกชื่อ อีเมลองค์กร แผนก และสิทธิ์เริ่มต้น
ระบบส่งอีเมลคำเชิญให้ผู้ใช้ตั้งรหัสผ่านเอง (ลิงก์อายุ 7 วัน)

> ผู้ดูแลระบบ **ไม่เห็นและไม่สามารถตั้งรหัสผ่าน** ของผู้ใช้ได้ — ตามหลักความปลอดภัย
> ถ้าผู้ใช้ลืมรหัสผ่าน ให้เขากด "ลืมรหัสผ่าน" เอง

### แก้สิทธิ์และสถานะบัญชี

กด **แก้สิทธิ์** ที่แถวของผู้ใช้ เลือก Role ได้หลายอย่างพร้อมกัน

**สถานะบัญชี**

| สถานะ | ความหมาย |
|---|---|
| รอตั้งรหัสผ่าน | ถูกเชิญแล้วแต่ยังไม่ตั้งรหัสผ่าน |
| ใช้งานได้ | ปกติ |
| **ถูกระงับ** | เข้าสู่ระบบไม่ได้ทันที (ใช้เมื่อสงสัยว่าบัญชีถูกยึด) |
| **ปิดบัญชี** | ใช้เมื่อพนักงานพ้นสภาพ — ประวัติการจองยังอยู่ครบ |

> พนักงานลาออกให้ตั้งเป็น **ปิดบัญชี** ไม่ต้องลบ เพื่อให้รายงานย้อนหลังยังถูกต้อง

### การเปลี่ยนสิทธิ์ถูกบันทึกทุกครั้ง

ทุกการให้/ถอนสิทธิ์ถูกบันทึกลง **บันทึกการใช้งาน** พร้อมค่าเดิมและค่าใหม่
ลบหรือแก้ย้อนหลังไม่ได้

## 5. อนุมัติคำขอ

**เมนู:** รออนุมัติ (แสดงเฉพาะผู้มีสิทธิ์)

แต่ละคำขอแสดงหัวข้อ ห้อง วัน เวลา จำนวนคน ผู้ขอ แผนก และวัตถุประสงค์

| ปุ่ม | ผลที่เกิด |
|---|---|
| **อนุมัติ** | สถานะเป็น "ยืนยันแล้ว" และตั้งเวลาเตือนก่อนประชุมให้ผู้จอง |
| **ปฏิเสธ** | สถานะเป็น "ถูกปฏิเสธ" ห้องว่างคืน — **ต้องระบุเหตุผล** |
| **ขอข้อมูลเพิ่ม** | แจ้งผู้จองให้ส่งข้อมูลเพิ่ม โดยคำขอยังรออนุมัติอยู่ |

ผู้จองได้รับแจ้งผลทุกกรณีทางอีเมล LINE และในระบบ

> ถ้าอนุมัติแล้วพบว่าช่วงเวลานั้นถูกจองไปก่อนแล้ว ระบบจะปฏิเสธการอนุมัติ
> และบอกว่าชนกับรายการใด

## 6. รายงาน

**เมนู:** ผู้ดูแลระบบ → รายงาน

กรองตามช่วงวันที่และห้อง แล้วดูตัวเลขเหล่านี้

| ตัวเลข | อ่านอย่างไร |
|---|---|
| จำนวนการจอง | รวมทุกสถานะในช่วงที่เลือก |
| ยืนยันแล้ว | นับรายการที่ใช้ห้องจริง |
| การยกเลิก | สูงผิดปกติ = อาจต้องทบทวนนโยบายหรือจำนวนห้อง |
| ไม่มาใช้ห้อง | สูง = ควรเปิด "ต้องเช็กอิน" เพื่อคืนห้องให้คนอื่น |
| ชั่วโมงการใช้งาน | รวมเวลาที่ห้องถูกใช้จริง |
| อัตราการใช้ห้อง | ชั่วโมงใช้งาน ÷ ชั่วโมงเปิดทำการทั้งหมด |
| ช่วงเวลาที่ใช้มากที่สุด | ใช้วางแผนว่าควรเพิ่มห้องช่วงใด |

**ดาวน์โหลด CSV** — ไฟล์มี BOM ให้ Excel เปิดภาษาไทยได้ถูกต้อง
สิ่งที่เห็นในไฟล์จำกัดตามสิทธิ์ของคุณ

**ตัวเลขที่ควรดูทุกเดือน**

- อัตราการใช้ห้องเกิน 80% ต่อเนื่อง → ห้องไม่พอ ควรเพิ่มห้องหรือจำกัดระยะเวลาจอง
- ไม่มาใช้ห้องเกิน 10% → เปิด "ต้องเช็กอิน" ในห้องที่เป็นปัญหา
- การยกเลิกกระจุกที่ห้องใดห้องหนึ่ง → ตรวจว่าห้องนั้นมีปัญหาอุปกรณ์หรือไม่

## 7. บันทึกการใช้งาน (Audit Log)

**เมนู:** ผู้ดูแลระบบ → บันทึกการใช้งาน

ค้นหาได้ตามอีเมลผู้กระทำ ประเภทการกระทำ และช่วงวันที่
แต่ละแถวกางดู "ค่าเดิม / ค่าใหม่" ได้

| ประเภทการกระทำ | เกิดเมื่อ |
|---|---|
| `auth.login`, `auth.login_rate_limited` | เข้าสู่ระบบ / ถูกจำกัดเพราะพยายามบ่อยเกินไป |
| `booking.create`, `booking.update`, `booking.cancel` | สร้าง/แก้/ยกเลิกการจอง |
| `booking.approved`, `booking.rejected` | ผลการอนุมัติ |
| `booking.check_in` | เช็กอิน |
| `room.create`, `room.update`, `room.archive` | จัดการห้อง |
| `room.closure_create` | ปิดห้องกะทันหัน |
| `role.grant` | เปลี่ยนสิทธิ์ผู้ใช้ |
| `user.invite` | เชิญผู้ใช้ |
| `notification.requeue` | สั่งส่งการแจ้งเตือนใหม่ |

**บันทึกนี้แก้ไขหรือลบไม่ได้** แม้เป็นผู้ดูแลระบบสูงสุด — ฐานข้อมูลบังคับไว้
เพื่อให้ใช้เป็นหลักฐานได้จริง

IP ถูกเก็บเพียงช่วงเครือข่าย (เช่น `203.0.113.0/24`) ไม่เก็บ IP เต็ม
เพื่อลดข้อมูลส่วนบุคคลตามแนวทาง PDPA

ระยะเวลาเก็บปรับได้ผ่านค่า `audit.retention_days` (ค่าปริยาย 730 วัน)

## 8. สถานะระบบ

**เมนู:** ผู้ดูแลระบบ → สถานะระบบ

| การ์ด | ความหมาย | ต้องทำอะไรเมื่อผิดปกติ |
|---|---|---|
| ผู้ให้บริการอีเมล / LINE | ถ้าขึ้น "โหมดทดสอบ (log)" คือยังไม่ส่งออกจริง | ตั้งค่า provider และคีย์ใน Vercel แล้ว Redeploy |
| งานค้างในคิว | จำนวนงานที่รอส่ง | ถ้าค้างเกิน 15 นาที ให้ตรวจว่า Cron ทำงานอยู่ |
| งานที่ล้มเหลวถาวร | ส่งไม่สำเร็จจนครบจำนวนครั้ง | ดู "ความผิดพลาดล่าสุด" แล้วแก้ที่ต้นเหตุ แล้วกด "ลองส่งใหม่" |
| อีเมลที่ถูกระงับส่ง | อีเมลที่ตีกลับหรือถูกรายงานสแปม | ตรวจว่าอีเมลผู้ใช้ถูกต้อง |
| ผู้ใช้ที่เชื่อม LINE | จำนวนคนที่รับแจ้งเตือนทาง LINE ได้ | – |
| งานที่ค้างนานสุด | อายุของงานที่เก่าที่สุดในคิว | ถ้าเกิน 15 นาที = Cron อาจหยุดทำงาน |

หน้านี้ **ไม่แสดงค่า secret ใด ๆ** แสดงเพียงชื่อผู้ให้บริการ

รายละเอียดการแก้แต่ละอาการอยู่ใน [runbooks.md](runbooks.md)

## 9. งานที่ระบบทำให้อัตโนมัติ

| งาน | ความถี่ | ทำอะไร |
|---|---|---|
| ส่งการแจ้งเตือน | ทุก 5 นาที | ส่งอีเมล/LINE จากคิว retry ให้เองถ้าล้มเหลว |
| งานดูแลระบบ | ทุก 10 นาที | ปล่อยห้องที่ไม่เช็กอิน, ปิดงานที่ผ่านไปแล้ว, จัดการคิวรอที่หมดเวลา, ล้างข้อมูลหมดอายุ |

ถ้างานเหล่านี้ไม่ทำงาน (คิวค้าง) ให้ตรวจ Vercel → Cron Jobs
และค่า `CRON_SECRET` ตาม [runbooks.md](runbooks.md#เหตุการณ์-อีเมลไม่ออก)

## 10. สิ่งที่ผู้ดูแลระบบควรทำตามรอบ

| ความถี่ | งาน |
|---|---|
| ทุกวัน | ดูหน้า **สถานะระบบ** ว่าไม่มีงานค้างหรือล้มเหลวถาวร |
| ทุกสัปดาห์ | ดูคิวรออนุมัติว่าไม่มีคำขอค้างนาน |
| ทุกเดือน | ดูรายงานอัตราการใช้ห้องและ "ไม่มาใช้ห้อง" แล้วปรับนโยบายห้อง |
| ทุกไตรมาส | ทบทวนรายชื่อผู้มีสิทธิ์ ปิดบัญชีพนักงานที่พ้นสภาพ |
| ทุก 6–12 เดือน | หมุนเวียนคีย์ (secret rotation) ตาม [infrastructure-setup.md](infrastructure-setup.md#82-การหมุนเวียนและเพิกถอนคีย์-secret-rotation) |
| ปีละครั้ง | ทดสอบกู้คืนฐานข้อมูลจาก backup จริง และบันทึกผล |
| เมื่อพนักงานพ้นสภาพ | ปิดบัญชี และหมุนเวียนคีย์ถ้าเขาเคยเข้าถึง |

## 11. สิ่งที่ห้ามทำ

| ห้าม | เพราะอะไร |
|---|---|
| ลบแถวในตาราง `bookings` ด้วยมือ | รายงานและ audit trail จะเพี้ยน — ให้เปลี่ยนสถานะเป็นยกเลิกแทน |
| ลบ constraint `bookings_no_overlap` | ระบบจะกันการจองซ้อนไม่ได้อีก |
| แก้ข้อมูลในตาราง `audit_logs` | ฐานข้อมูลกันไว้แล้ว และทำให้บันทึกใช้เป็นหลักฐานไม่ได้ |
| ใช้บัญชีตัวอย่างจาก seed บน production | รหัสผ่านอยู่ในเอกสารสาธารณะ |
| ใส่ `DIRECT_URL` ใน Vercel | เสี่ยงเปิด connection เต็มโควตาจนเว็บล่ม |
| แชร์คีย์หรือ connection string ในแชต | ถือว่าคีย์รั่ว ต้องหมุนเวียนใหม่ทันที |
