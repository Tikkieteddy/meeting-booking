## 4. การติดตั้งเป็นแอฟบนมือถือ (PWA)

ใช้งานในเบราว์เซอร์ได้ตามปกติทุกอย่าง การติดตั้งเป็นแอฟเป็นของแถมที่ใครอยากใช้ก็กดได้
เบราว์เซอร์ที่ไม่รองรับจะเพิกเฉยและไม่มีอะไรเสียไป (progressive enhancement)

| ส่วนประกอบ | ที่อยู่ |
|---|---|
| ข้อมูลสำหรับติดตั้ง | `src/app/manifest.ts` → เสิร์ฟที่ `/manifest.webmanifest` |
| ไอคอน (192, 512, maskable 512, apple 180) | `public/icons/` สร้างด้วย `node scripts/generate-icons.mjs` |
| ตัวจัดการแคช | `public/sw.js` |
| ตัวลงทะเบียน | `src/components/pwa/register-service-worker.tsx` |
| หน้าที่แสดงตอนเน็ตล่ม | `src/app/offline/page.tsx` |
| วิธีติดตั้งสำหรับผู้ใช้ | อยู่ในหน้า **ช่วยเหลือ** ของระบบ แยกตาม Android / iOS / คอมพิวเตอร์ |

### กฎความปลอดภัยของแคช — อ่านก่อนแก้ `public/sw.js`

**ห้ามแคชหน้า HTML ที่มีข้อมูลผู้ใช้ และห้ามแคชคำตอบจาก `/api/` เด็ดขาด**

หน้าเว็บของระบบนี้ถูกประกอบที่เซิร์ฟเวอร์พร้อมข้อมูลของคนที่ล็อกอินอยู่
(ชื่อ อีเมล รายการประชุม สิทธิ์) ถ้าแคชไว้ในเครื่องที่ใช้ร่วมกัน เช่นแท็บเล็ต
หน้าห้องประชุม คนถัดไปที่เปิดอาจเห็นข้อมูลของคนก่อนทั้งที่ล็อกเอาต์ไปแล้ว

| แคชได้ | เหตุผล |
|---|---|
| `/_next/static/...` | ชื่อไฟล์มี hash เปลี่ยนทุก build ไม่มีข้อมูลของใคร |
| `/icons/...` | ภาพนิ่ง ไม่มีข้อมูลของใคร |
| `/offline` | หน้าคงที่ ไม่ต้องล็อกอิน ไม่แตะฐานข้อมูล |

| ห้ามแคช | เหตุผล |
|---|---|
| `/api/...` ทุกเส้นทาง | เป็นข้อมูลสดและเป็นข้อมูลส่วนบุคคล |
| หน้า HTML ทุกหน้า | มีข้อมูลของผู้ที่ล็อกอินอยู่ |
| คำขอที่ไม่ใช่ GET | การสร้าง/แก้/ลบ ต้องถึงเซิร์ฟเวอร์ทุกครั้ง |

ข้อห้ามเหล่านี้ถูกบังคับด้วยเทสต์ใน `tests/e2e/pwa.spec.ts` — ถ้าวันหนึ่งมีคนแก้
`sw.js` ให้แคชหน้า HTML เพื่อให้เว็บเร็วขึ้น เทสต์จะแดงทันที

**ผลที่ได้จริง:** เปิดครั้งแรกโหลด ~157–172 KiB ตามปกติ
เปิดครั้งที่สองขึ้นไป JavaScript และ CSS (ประมาณ 110 kB) อ่านจากเครื่อง
ส่วนข้อมูลการจองยังดึงสดจากเซิร์ฟเวอร์ทุกครั้งเสมอ

## 5. การประหยัดเน็ตของผู้ใช้

Next.js โหลดหน้าถัดไปล่วงหน้าให้ทันทีที่ลิงก์ปรากฏบนจอ เมนูของระบบนี้อยู่ทุกหน้า
บนเน็ตมือถือจึงกินเน็ตไปกับหน้าที่ผู้ใช้อาจไม่กดเลย

`src/components/ui/smart-link.tsx` ปิดพฤติกรรมนี้เมื่อ:

1. ผู้ใช้เปิดโหมดประหยัดเน็ตในเครื่อง (Data Saver)
2. เน็ตช้ากว่า 4G (`slow-2g`, `2g`, `3g`)

**วัดได้จริง** (`tests/e2e/network-saving.spec.ts`):

| สภาพเน็ต | คำขอโหลดล่วงหน้าต่อการเปิดหน้าปฏิทิน 1 ครั้ง |
|---|---|
| เน็ตปกติ / 4G | 2 คำขอ (ได้ประโยชน์ กดแล้วไว) |
| โหมดประหยัดเน็ต | **0 คำขอ** |
| เน็ต 3G หรือช้ากว่า | **0 คำขอ** |
| เบราว์เซอร์ที่ไม่บอกข้อมูลเครือข่าย (Safari, Firefox) | 2 คำขอ (พฤติกรรมเดิม ไม่ถูกลงโทษ) |

## 6. เรื่อง polyfill — ข้อที่เข้าใจผิดกันบ่อย

Next.js สร้างไฟล์ `polyfills-*.js` ขนาดประมาณ 39 kB ไว้สำหรับเบราว์เซอร์รุ่นเก่า
เมื่อดู HTML ที่เซิร์ฟเวอร์ส่งออกมาจริงจะพบว่าแท็บนี้มีแอตทริบิวต์ `noModule`:

```html
<script src="/_next/static/chunks/polyfills-42372ed130431b0a.js" noModule=""></script>
```

`noModule` หมายถึง **เบราว์เซอร์รุ่นใหม่ข้ามไฟล์นี้ไปเลยตั้งแต่แรก** ไม่ได้ดาวน์โหลด
ดังนั้นการ "ตัด polyfill เพื่อลด 39 kB" ไม่มีอยู่จริง — มือถือรุ่นใหม่ไม่เคยโหลดอยู่แล้ว

ที่ยังทำได้คือตั้ง `browserslist` ให้ตรงกับเบราว์เซอร์ที่รองรับจริง ซึ่งวัดแล้ว
**ลดได้ 1.9 kB (0.7%)** — เก็บค่านี้ไว้เพราะมันถูกต้องเชิงหลักการ (ระบุชัดว่ารองรับ
เบราว์เซอร์รุ่นไหน ให้ตรงกับที่ Tailwind CSS 4 ต้องการอยู่แล้ว) ไม่ใช่เพราะลดขนาดได้มาก

ค่าที่ตั้งไว้ใน `package.json`:

```
chrome >= 111, edge >= 111, firefox >= 128, safari >= 16.4, ios_saf >= 16.4
```

## 7. ปัญหา accessibility ที่ Lighthouse จับได้ และที่แก้ไปแล้ว

การวัดครั้งแรกได้ Accessibility 96/100 และพบปัญหาที่มีอยู่ก่อนแล้วหลายจุด
ทุกข้อด้านล่างนี้ **แก้แล้ว**:

| ปัญหา | อัตราส่วนความต่างที่วัดได้ | แก้เป็น |
|---|---|---|
| `--color-ink-500` ใช้เป็นสีข้อความทั่วระบบ | 4.39:1 บนขาว, 4.24:1 บน ink-50 (ต้อง 4.5) | `#76726a` → 4.79:1 และ 4.51:1 |
| ป้ายนับเวลาสีแดงในตารางรายวัน | 3.81:1 | `bg-red-600` → 4.77:1 |
| ข้อความเมนูล่างบนมือถือตอนเลือกอยู่ | 4.36:1 | `text-brand-700` → 6.1:1 |
| โลโก้ตัว "T" ทำให้ชื่อลิงก์ไม่ตรงกับข้อความที่ตาเห็น | — | ใช้ SVG (`BrandMark`) แทนตัวอักษร |
| การ์ดการจองมี `aria-label` ที่หลุดจากข้อความที่แสดง | — | เลิกใช้ `aria-label` ให้ชื่อมาจากเนื้อหาจริง + `sr-only` บอกสถานะ |

สองข้อท้ายเป็นเรื่องกฎ **WCAG 2.5.3 (Label in Name)** ซึ่งกำหนดว่าชื่อที่
screen reader อ่าน ต้องครอบคลุมข้อความที่ตาเห็น เพราะคนที่สั่งงานด้วยเสียงจะพูด
ตามที่เห็นบนจอ ถ้าบนจอเขียน `09:00–10:30` แต่ `aria-label` เขียน `09:00 ถึง 10:30`
คำสั่งเสียงจะหาปุ่มนั้นไม่เจอ

### ข้อที่ยังไม่ผ่าน — ต้องให้ฝ่ายแบรนด์ตัดสิน

เหลือข้อเดียว คือ **ตัวอักษรขาวบนพื้นสีส้มแบรนด์ `#EC5F27`** ซึ่งได้ **3.36:1**
ไม่ถึงเกณฑ์ WCAG AA (4.5:1) — ปรากฏที่ปุ่มหลัก ปุ่มยืนยัน ป้ายแจ้งเตือน
และวงกลมวันที่ในมุมมองเดือน

นี่เป็นความขัดแย้งระหว่างข้อกำหนดสองข้อในบรีฟ: บรีฟกำหนดสีแบรนด์ `#EC5F27`
และกำหนดว่าต้องผ่านเกณฑ์การเข้าถึงด้วย ทางเลือกที่มี:

## 8. วิธีวัดซ้ำด้วยตัวเอง

```bash
npm run build
npx next start -p 3100 &
npm run lighthouse -- http://127.0.0.1:3100/login
# ได้ไฟล์ lighthouse-report.html เปิดดูในเบราว์เซอร์ได้เลย
```

ถ้า Chrome ไม่ได้อยู่ที่ตำแหน่งมาตรฐาน ให้ระบุด้วย `CHROME_PATH=<พาธของ Chrome>`
สคริปต์นี้**ไม่ใส่ `--preset`** โดยเจตนา เพื่อให้ได้โหมดมือถือซึ่งเป็นค่าเริ่มต้น
และเป็นโหมดเดียวกับตัวเลขทั้งหมดในเอกสารนี้

หน้าที่ต้องล็อกอิน (เช่น `/calendar`) ต้องส่ง cookie ไปด้วย:

```bash
# สร้างไฟล์ {"Cookie":"tnn_session=..."} แล้วส่งด้วย --extra-headers=<ไฟล์>
# ★ ไฟล์นั้นมีค่า session ของจริง ห้าม commit และควรลบทิ้งหลังใช้
```

รายงาน JSON ของ Lighthouse บันทึกค่า header ที่ส่งไปด้วย
**จึงห้ามเก็บไฟล์รายงานของหน้าที่ต้องล็อกอินไว้ในโปรเจกต์**

## 9. ความปลอดภัยของ dependency

ตรวจด้วย `npm run audit:prod` (ย่อจาก `npm audit --omit=dev`) ซึ่งดูเฉพาะ
แพ็กเกจที่ขึ้น production จริง ไม่รวมเครื่องมือของนักพัฒนา

**ผลปัจจุบัน: found 0 vulnerabilities**

ตอนตรวจครั้งแรกพบ 3 รายการ มาจากแพ็กเกจที่ `next` ดึงมาให้เอง:

| แพ็กเกจ | ปัญหา | แก้เป็น |
|---|---|---|
| `postcss` 8.4.31 | path traversal ผ่าน `sourceMappingURL` และ XSS ใน CSS stringify (4 advisory) | `^8.5.28` |
| `sharp` 0.34.5 | ช่องโหว่ที่สืบทอดจาก libvips และ libheif | `^0.35.4` |

แก้ด้วย `overrides` ใน `package.json` เพราะทั้งสองตัวเป็น dependency ชั้นในของ
`next` ไม่ได้ประกาศไว้เอง จึงบังคับเวอร์ชันจากด้านนอก ยืนยันแล้วว่า build ผ่าน
CSS ที่ได้ขนาดใกล้เคียงเดิม (8,154 → 8,184 ไบต์ ต่างกัน 30 ไบต์)
และเทสต์ทั้ง 311 รายการยังผ่านครบ (unit 80 + integration 55 + e2e 176)

### ยังค้างอยู่ — เครื่องมือของนักพัฒนา

`npm audit` แบบเต็ม (รวม dev) ยังพบ 5 รายการจาก **`vitest` 2.1.9**
สาย 2.x ไม่มีเวอร์ชันที่แก้แล้ว ต้องข้ามไป 5.x

ยังไม่ได้อัปเกรดเพราะเป็นการข้าม 3 major version ซึ่งไม่ใช่ขอบเขตของงานรอบนี้
และความเสี่ยงจริงต่ำ: ไม่ได้ขึ้น production เลย และรายการระดับ critical
(อ่าน/รันไฟล์ได้ตามใจ) เกิดเฉพาะเมื่อเปิด `vitest --ui` ซึ่งโปรเจกต์นี้ไม่ใช้

`vitest.config.ts` และ `vitest.integration.config.ts` ใช้ option พื้นฐานทั้งหมด
(`resolve.alias`, `include`, `globalSetup`, `fileParallelism`) ซึ่งยังรองรับใน
เวอร์ชันใหม่ จึงคาดว่าอัปเกรดแล้วแก้ไม่มาก — ควรทำเป็นงานถัดไป
