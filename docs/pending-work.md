# งานค้าง

รายการสิ่งที่ต้องทำแต่ยังไม่ได้ทำ — อัปเดตทุกครั้งที่ปิดงานหรือมีงานใหม่ (กฎใน CLAUDE.md)
ปรับล่าสุด: 2 ต.ค. 2569

## รอผู้ใช้ทำ / ตัดสินใจ

| งาน | ทำไมต้องทำ | ทำที่ไหน |
|---|---|---|
| เปิดวันเสาร์–อาทิตย์ให้ห้องที่มีอยู่แล้ว | ห้องเดิมเปิดแค่ จ.–ศ. จองหรือย้ายไปเสาร์–อาทิตย์ไม่ได้ (ห้องที่สร้างใหม่เปิดทุกวันแล้ว) | เว็บ → จัดการห้อง → แก้ไข → เวลาทำการ → กด ส. อา. |
| ตั้ง `LINE_BOT_BASIC_ID` ใน Vercel | ให้หน้าโปรไฟล์มีปุ่ม "เพิ่มเพื่อน LINE" พนักงานไม่ต้องค้นหา ID เอง | Vercel → Settings → Environment Variables แล้ว Redeploy |
| ตั้งโดเมนอีเมลที่สมัครได้ (`AUTH_ALLOWED_EMAIL_DOMAINS`) | ถ้ายังไม่ได้ตั้ง ใครมีอีเมลอะไรก็สมัครได้ (ยังไม่ได้ตรวจค่าบน Vercel) — ควรจำกัดเป็นอีเมลบริษัท | ต้องได้ชื่อโดเมนอีเมลบริษัทก่อน |
| ข้อมูลห้องและอาคารจริง | ยังเป็นห้องที่สร้างทดลอง | ชื่อห้อง ความจุ ชั้น อุปกรณ์ |
| ผู้ดูแลระบบสูงสุดคนที่ 2 | ถ้าบัญชีเดียวเข้าไม่ได้ จะไม่มีใครจัดการระบบได้ | ระบุชื่อ+อีเมลคนที่ 2 |
| เบอร์ IT Helpdesk (`HELPDESK_CONTACT`) | บรรทัดติดต่อ Helpdesk ในหน้าเข้าสู่ระบบ | รอเบอร์ |
| SSO (เข้าสู่ระบบด้วยบัญชีบริษัท) | ตามแบบจาก Stitch | ต้องได้ข้อมูลจากฝ่าย IT ว่าใช้ระบบอะไร |

## รอ Claude ทำ (เรียงตามความสำคัญ)

| งาน | หมายเหตุ |
|---|---|
| เชื่อมอีเมลจริง (Resend) | ระหว่างนี้: เชิญผู้ใช้ได้ด้วยลิงก์ที่คัดลอกไปส่งเอง, คนนอกยังไม่ได้รับแจ้งเตือน — ผู้ใช้ต้องสมัคร Resend และยืนยันโดเมนด้วย |
| ไอคอนเป็นเส้น แทนอีโมจิ | ตามแบบจาก Stitch |
| แถบเครื่องมือบนมือถือสูงเกินไป | ตามแบบจาก Stitch |
| ฟอร์มจองมีทั้งช่องเลือกห้องและการ์ดห้องซ้ำกัน | ตามแบบจาก Stitch |

## ข้อควรรู้ (ไม่ใช่งาน แต่เป็นผลของการตัดสินใจ)

- แก้/ยกเลิกได้เฉพาะการจองที่ตัวเองสร้าง **รวมผู้ดูแลระบบ** — ถ้าพนักงานลาออกโดยมีการจองค้าง จะไม่มีใครยกเลิกแทนได้
  ถ้าต้องการให้ผู้ดูแลทำแทนได้ แก้ที่ `assertOwner` ใน `src/lib/domain/booking-service.ts`
- ปิดขั้นตอนผู้อนุมัติไว้ในการใช้งาน (โค้ดยังอยู่) ถ้าจะเปิดใช้ ต้องตัดสินใจว่าการย้ายวัน/ห้องต้องขออนุมัติใหม่หรือไม่ (ADR-018)
